# Connect Digitals Agency AMS — Phase 1 implementation

This change builds the full Phase 1 admin application from scratch: project scaffold, auth shell, client management, project management, and dashboard overview. The approach is React + Vite + TypeScript with Tailwind CSS and Supabase, staying strictly within the specified stack and dependency versions. All 26 required files are present. The build artifact (`dist/index.html` + CSS/JS bundles) exists and FEAT-003 findings confirm `npm run build` exited 0 with no TypeScript errors across 1689 modules.

Watch for: (1) **confirmed** — LoginPage does not redirect already-authenticated users away from `/login`; a signed-in admin who navigates directly to `/login` sees the sign-in form instead of being sent to the dashboard. (2) **confirmed** — archive action on ClientsPage fires without any confirmation prompt; one misclick permanently archives a client with no recovery path in the UI. (3) **possible** — `bg-gold` is never applied as a background in any UI component; gold is used only as text and borders — confirm this covers the design intent.

**Verdict**: CHANGES_REQUESTED

## High-level view

The routing structure correctly separates the unprotected `/login` route from the admin routes behind `ProtectedRoute`, which redirects to `/login` on no session. The gap is the reverse direction: a signed-in admin who manually navigates to `/login` stays on the login page instead of being pushed to the dashboard. The plan explicitly specified this redirect.

The Supabase singleton in `src/lib/supabase.ts` is the only place `createClient` is called. Every consumer imports from that file. No `import.meta.env` access occurs outside it, no service-role key appears anywhere in `src/`, and the `.env` file is absent from the workspace.

Both SQL migrations enable RLS and define an `authenticated`-only policy with `USING (true) WITH CHECK (true)`, blocking all anonymous access. The `projects.status` column has a CHECK constraint enforcing the four allowed values at the database level.

Client archival in `ClientsPage` fires immediately on button click. The plan called out a confirmation step (inline or `window.confirm`) before the Supabase call. Without it there is no recovery path — the client disappears from the list and the UI provides no unarchive action.

All five brand colors are defined in `tailwind.config.js` at the exact specified hex values and are used across components. `bg-gold` is not applied as a background anywhere, which is consistent with the minimal design direction but worth confirming against intent.

<details>
<summary>Details</summary>

### Auth redirect gap on LoginPage

The plan says "If user is already logged in (check useAuth), redirect to '/' immediately." `LoginPage` calls `useAuth()` but only destructures `signIn`; `user` and `loading` are never read. A signed-in admin navigating to `/login` directly stays on the login page. The fix:

```tsx
const { signIn, user, loading } = useAuth();
useEffect(() => {
  if (!loading && user) navigate('/');
}, [user, loading, navigate]);
```

### Archive without confirmation

`handleArchive` is wired directly to the button's `onClick`. The plan explicitly called out "a confirmation inline or window.confirm" before the Supabase call. There is no unarchive action anywhere in the current UI, so the client is effectively gone from the admin's view until a database-level intervention. The risk is heightened because the archive icon sits immediately next to the edit icon in the same actions cell.

</details>
